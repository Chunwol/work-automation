# 근로장학생 일지 자동화

사용자별 로그인, 월간 일정 편집, 암호화된 학교 포털 계정 저장, 포털 기록 조회와 자동 입력을 제공하는 로컬 웹 애플리케이션입니다. 기존 JSON 기반 CLI도 함께 유지됩니다.

Docker 운영 배포와 GitHub Actions 설정은 [NAS 배포 안내](deploy/README.md)를 참고하세요.

## 웹 애플리케이션 실행

```powershell
npm install
npm start
```

브라우저에서 `http://127.0.0.1:3210`을 엽니다. `회원가입` 탭에서 누구나 자신의 웹 계정을 만들 수 있습니다.

1. `회원가입`에서 표시 이름, 아이디, 비밀번호와 비밀번호 확인 입력
2. `학교 포털 계정`에서 아이디와 비밀번호 입력 후 `확인 후 저장`: 실제 로그인·SSO와 근로 일지 접근 확인에 성공한 경우에만 암호화하여 등록
3. 달력 또는 `요일 반복 설정`으로 월간 일정 작성
4. `배정 조회·선택`에서 해당 월에 승인된 장학 유형과 근무지 선택
5. `일정 저장` 후 `기록만 조회`로 기존 포털 기록 확인
6. 최종 확인 후 `자동 입력 시작`

회원가입은 항상 일반 사용자로 생성되고 즉시 로그인됩니다. 학교 포털 비밀번호는 앱 비밀번호와 별도로 등록합니다. 일반 사용자는 자신의 포털 계정, 일정, 작업 이력만 볼 수 있습니다. 서버 운영자는 별도의 `서버 관리자 초기 설정`으로 관리자 계정을 만들 수 있고, 관리자는 `사용자 관리`에서 계정을 관리할 수 있습니다.

포털 인증 실패·점검·통신 오류 시 입력한 연결정보를 저장하지 않고 기존 연결을 유지합니다. 확인에는 로그인과 조회 API만 사용하며 실제 일지는 변경하지 않습니다. 중복 확인과 진행 중인 포털 작업의 계정 교체를 막고, 사용자·포털 계정·IP별 확인 횟수를 제한합니다.

### 달력과 포털 일지 관리

- 반복 설정과 단일 날짜의 `구간 추가`로 하루 최대 8개 근무 구간을 입력할 수 있습니다. 점심 등 구간 사이의 시간은 합계에서 제외되며, 겹치는 구간은 저장할 수 없습니다. 날짜별 설정은 그날의 반복 구간 전체를 대체합니다. 드래그 복사는 그날의 수동 구간 전체를 복사합니다.
- 시간은 오전/오후 없는 24시간제로 입력합니다. 입력칸에 처음 포커스하면 기존 값이 선택되어 바로 덮어쓸 수 있습니다. `9`, `930`, `0900`, `09:00`처럼 입력하면 각각 `09:00`, `09:30`, `09:00`, `09:00`으로 정리됩니다. 퇴근은 `24:00`까지 가능하며 출근으로는 허용하지 않습니다. 실제 포털 처리는 구간별로 기존 시간 제한과 조회·검증을 그대로 거칩니다.

- `기록만 조회` 완료 후 기존 포털 일지를 달력에 표시합니다. 국가/일반근로를 구분하고, 입력 예정 시수와 조회된 포털 시수는 별도로 표시합니다.
- 조회 결과는 사용자·월별 마지막 성공 결과로 복원합니다. 화면의 조회 시각 이후 변경 사항은 다시 조회해야 하며, 학교 계정을 변경하면 이전 조회 결과를 표시하지 않습니다.
- 날짜를 누르면 포털 기록의 시간·근무내용·근무지·확인 상태를 볼 수 있습니다. 미확인 기록은 `포털 일지 수정` 또는 `포털 일지 삭제`로 실제 처리할 수 있습니다.
- 수정·삭제 전 확인란에 동의해야 하며 서버에서 원본·계정·배정·확인 상태를 다시 조회합니다. 확인 완료 기록이나 조회 후 바뀐 기록은 변경하지 않습니다. 처리 후 재조회로 결과를 검증합니다.
- 수정은 같은 날짜/배정의 시간과 근무내용을 대상으로 합니다. 날짜나 배정을 잘못 등록했다면 미확인 기록을 삭제하고 올바른 일정으로 다시 등록하세요. 담당자 승인/확인 권한은 제공하지 않습니다.
- 일요일과 공휴일을 빨간색으로 표시합니다. Google 대한민국 공휴일 달력의 공휴일은 반복 일정에서 기본 제외되고, `공휴일 근무`를 선택하면 해당 날짜의 제외를 해제할 수 있습니다. 학교 포털의 별도 공휴일 등록 제한은 우회하지 않습니다.
- `요일 반복 설정`은 내 계정의 현재 월 공통 시간표입니다. 적용 전에 예상 일수/시수 확인 알림을 띄우고, 날짜별 설정과 제외일은 유지합니다.
- `예정 일정만 삭제`는 수동 일정만 있는 날을 빈 날짜로 돌립니다. 해당 요일의 반복 일정이 있으면 그날만 반복에서 제외하며 포털 기록은 유지합니다. 실제 포털 삭제와는 별도 기능입니다.
- 신규 자동입력은 현재 월에 선택한 배정 하나를 사용합니다. 한 달 중 배정이 바뀌는 경우 날짜별 배정 자동 분리는 아직 지원하지 않습니다. 조회·수정·삭제는 각 기록의 원래 배정을 기준으로 처리합니다.

### 저장 위치와 보안

- 앱 데이터: `data\worklog.db`
- 로컬 암호화 키: `data\.master-key`
- 앱 로그인 비밀번호: `scrypt` 단방향 해시
- 포털 아이디·비밀번호: AES-256-GCM 암호문
- 로그인 세션: 해시된 임의 토큰과 HttpOnly/SameSite 쿠키
- 주요 변경: 감사 로그 기록

로컬 개발 모드에서는 처음 실행할 때 암호화 키가 자동 생성됩니다. 인터넷 또는 교내망에 공개할 때는 `.env.example`을 참고하여 `NODE_ENV=production`, HTTPS, `COOKIE_SECURE=true`, 별도 `APP_MASTER_KEY`를 설정해야 합니다. 데이터 복구에는 데이터베이스와 암호화 키가 모두 필요하므로 함께 백업하되 접근 권한은 제한하세요.

### 검사 명령

```powershell
npm test
npm run test:ui
npm run test:calendar-ui
npm run audit:security
npm run inspect:portal-api
npm run test:portal-live
npm run test:portal-login
npm run test:portal-dry-run
```

`inspect:portal-api`, `test:portal-live`, `test:portal-dry-run`은 `users\LSH.json`으로 로그인해 조회 또는 저장 없는 검토 실행만 수행합니다. 신규·저장·삭제 요청은 보내지 않으며 민감한 값은 출력에서 가립니다. 자세한 결과는 `docs\portal-api-findings.md`를 참고하세요.

웹 실행 경로는 브라우저 자동화 없이 HTTP 로그인, SSO 쿠키, 메뉴 권한 확인, JSON API만 사용합니다. `OnLoad`, `FindWork`, `Chgdeptcd`, `Bef`, `List`, `Checkweek`, `Vacation`, `Holi`, `Save`를 용도별로 호출합니다. 배정이 여러 개면 사용자가 선택해야 하며 각 저장 직전에 다시 검증합니다. 기존 Puppeteer 의존성은 CLI와 화면 테스트·진단용입니다.

예정된 근무도 미리 포털로 전송할 수 있으며, 앱에서 근무 종료 시각을 기준으로 등록·수정을 막지 않습니다. 실제 접수 여부는 학교 포털의 검증에 따릅니다. 최소 1시간·30분 단위 근무, 장학 유형별 시작시간 단위, 하루 8시간, 승인 기간, 공휴일, 적용되는 주·월·학기 한도를 검사합니다. `limit_yn=Y`는 학기 한도 예외이며 입력 금지 신호가 아닙니다. 공휴일 기본 제외와 사용자의 근무 예외는 달력/미리보기/저장에 동일하게 적용하고, 실제 전송 시에는 학교 포털의 제한을 별도로 검증합니다.

2026-09-04 테스트 계정으로 9월 1일 13:00~14:00 임시 행을 등록하고, 중복 제외·13:00~15:00 및 내용 수정·오래된 원본 변경 차단·삭제·재조회를 실제 HTTP API로 검증했습니다. 최종 9월 기록은 테스트 전과 같은 0건이며, 8월 19건은 읽기 전용으로 전후 동일함을 확인했습니다. 쓰기 테스트는 일반 테스트에 포함되지 않으며 재실행에는 별도 승인이 필요합니다. 앱 API 목록은 `docs/web-api.md`를 참고하세요.

수동으로 추가한 예정 일정은 다른 날짜로 드래그하여 복사할 수 있습니다. 빈 날짜에는 확인창 없이 복사하고 원본을 유지합니다. 공휴일·추가 지정 휴일이거나 기존 예정 일정·포털 기록이 있는 날짜에만 앱 확인 모달을 표시합니다. 같은 시간이 이미 예정되어 있으면 아무것도 바꾸지 않습니다. 모바일·키보드에서는 날짜 상세창의 `일정 복사`를 사용하세요. 복사는 현재 월의 시간만 복제하며, 근무내용·배정은 월 공통 설정을 사용합니다. `일정 저장`으로 보관하고 실제 포털 등록은 별도 자동입력 확인 후 실행합니다. 기존 포털 기록은 드래그 복사로 변경되지 않습니다.

사용법은 화면 상단의 `도움말`에 모았습니다. 시작하기, 일정 복사·삭제, 반복·공휴일, 포털 일지 관리, 지원 범위, 계정 보관을 항목별로 펼쳐볼 수 있으며 모바일과 키보드로도 이용할 수 있습니다. 메인 화면에는 실제 일정·배정·조회 시각만 표시하고, 오류 경고와 실제 포털 변경 확인은 해당 상황에서 유지합니다.

브라우저 기본 alert/confirm 대신 앱 모달을 사용합니다. 반복 적용·하루 일정 삭제·포털 연결정보 삭제는 확인 모달을 거치고, 확인 중 원본이 달라지면 적용을 중단합니다. 모달은 취소를 기본 포커스로 두며, 필수 입력값이 비어 있어도 닫을 수 있습니다. 작은 화면에서는 입력란을 재배치하고 헤더·실행 버튼을 스크롤 중에도 유지하며, 화면의 표시 영역 변화에 맞춰 높이를 조정합니다. 모바일 관리자 기능은 사용자 메뉴에서 열 수 있습니다.

`npm run test:modal-ui`는 모의 포털과 메모리 DB에서 모든 모달을 320/390/768/844/1440px 화면, 가로 방향 및 입력 중 축소 화면으로 검사합니다. 실제 iOS/Android 기기의 브라우저·가상 키보드 검증을 대신하지는 않으며 학교 포털 쓰기는 수행하지 않습니다.

## 반복 규칙과 자동 조회

웹앱의 근무내용은 선택 입력입니다(UTF-8 100바이트 이내). 비워두면 빈 내용 그대로 전송하며 실제 접수 여부는 학교 포털의 검증에 따릅니다.

요일 반복 규칙은 설정한 월부터 다음 변경 전까지 월·연도·학기 구분 없이 이어집니다. 변경한 월 이전과 이미 별도로 설정된 미래 월의 규칙은 유지합니다. 기존 월별 데이터는 최초 마이그레이션 때 보존합니다. 수동 일정·제외일·배정·근무내용은 월별로 남고, 월 이동 전 편집 중인 일정은 앱 DB에 저장합니다. 다른 화면에서 반복 규칙을 바꾸면 오래된 화면의 저장은 409로 거절합니다.

포털 연결 후 첫 접속과 월 이동 시 근무지·일지를 자동 조회합니다. DB의 마지막 성공 기록을 먼저 보여주고 백그라운드에서 갱신하며, 최근 1분 결과와 같은 월의 진행 중 조회는 재사용합니다. 빠른 월 이동은 마지막 월만 조회하고 기존 작업이 있으면 완료를 기다립니다. 실패해도 이전 기록·조회 시각은 유지합니다. 자동 조회는 학교 일지를 등록하거나 수정하지 않습니다.

`npm run test:auto-query-ui`는 모의 포털과 메모리 DB에서 초기 조회, 조회 중 캐시 표시, 빠른 월 이동, 실패 시 이전 기록 유지, 조회 재사용 및 월 이동 전 저장을 검증합니다. 실제 학교 기록은 변경하지 않습니다.

## 매월 예약 실행

`포털 자동화 → 매월 자동 실행`에서 월 1회 실행할 날짜(1~31일 또는 말일), 한국 시간, 대상 월(실행하는 달/지난달), 기본 배정을 설정합니다. 기본은 꺼짐이며 실제 포털 등록 동의를 확인해야 활성화됩니다. 사용자 PC나 브라우저가 꺼져도 NAS 서버가 실행 중이면 동작합니다.

대상 월에 저장한 일정·배정을 우선 사용하고, 없는 달은 해당 월의 유효한 반복 규칙과 예약 기본 배정을 사용합니다. 새 달의 근무내용은 빈 값이며 수동 예외는 상속하지 않습니다. 공휴일을 새로 계산하고 기존 포털 검증·중복 제외·전송 후 재조회와 전역 500ms 요청 간격을 그대로 적용합니다. 저장되지 않은 UI 편집은 예약 실행에 반영되지 않습니다.

서버는 30초 간격으로 만료된 예약을 확인합니다. 실행 이력과 작업 생성을 SQLite 트랜잭션으로 먼저 기록하므로 재시작·중복 tick에도 같은 시도를 재전송하지 않습니다. 29~31일이 없는 달은 말일에 실행합니다. 예약 저장 시 지난 시각은 다음 달부터 시작하며, 이미 시도한 달의 설정을 바꾸어도 즉시 재실행하지 않습니다. 중단으로 놓친 실행은 24시간까지만 지연 실행하고 그 이후는 실패 사유를 남깁니다.

배정 조회 결과에 선택한 장학·근무지가 없고 저장 요청을 한 번도 보내지 않은 경우만 승인 대기로 분류합니다. 다음 날 예약 시각에 같은 대상 월을 다시 확인하며 다음 정기 예약 전까지 하루 한 번 계속합니다. 대기 시각은 DB에 보관하고 설정창에 표시합니다. 예약 설정 변경·해제나 연결정보 변경으로 대기가 취소됩니다. 로그인·통신·형식 변경·근로시간 제한·저장 결과 불확실 오류는 승인 대기로 추정하지 않으며 자동 재시도하지 않습니다.

자동 입력 버튼과 매월 예약 모두 포털에 기록이 하나라도 있는 날짜는 장학·근무지·시간과 관계없이 전체를 건너뜁니다. 비어 있던 날짜에 이번 작업이 등록·검증한 구간은 다른 구간을 막지 않으므로 점심 전후 여러 구간을 모두 등록할 수 있습니다. 중간에 외부 기록이 생기면 남은 구간은 제외합니다.

`이전 달 가져오기`는 이전 달 앱 예정 일정을 현재 월의 같은 일자로 복사하고 입력 대기로 저장합니다. 기존 현재 월 예정 일정은 확인 후 교체하지만, 요일 반복 규칙·현재 배정·근무내용은 유지합니다. 없는 날짜는 제외하고 현재 월 공휴일을 적용합니다. 이 버튼 자체는 포털 등록·수정·삭제를 하지 않습니다.

포털 연결정보 변경/삭제, 사용자 비활성화 시 예약도 비활성화됩니다. 배포 준비 중에는 새 예약을 시작하지 않으며 실행 준비와 포털 작업은 기존 배포 busy 검사에 포함됩니다. 예약 해제는 다음 실행을 막지만 이미 전송한 일지를 되돌리지 않습니다. `최근 작업`과 예약 설정창에서 결과/다음 실행을 확인하세요.

`npm run test:monthly-ui`는 모의 포털·메모리 DB로 동의, 취소, 설정 저장/해제, 모바일 모달, 브라우저 종료 후 서버 실행을 검사합니다. 실제 학교 일지는 변경하지 않습니다.

## 포털 세션 재사용

조회·실행 사이의 유효한 로그인 쿠키는 계정·암호화된 연결정보 버전별로 서버 메모리에만 보관합니다. 재사용 전에 공식 연장 기능인 `POST /sys.Main.do`의 `Resettime`을 호출하고 MenuAuth/학생 정보/OnLoad 권한을 다시 확인하며 학생이 달라지면 중단합니다. 만료가 확인되면 재로그인하고, 진행 중 만료된 조회만 최대 한 번 다시 조회할 수 있습니다. 다른 곳에서 로그인하여 세션이 끊기는 경우에도 재로그인 경로를 유지합니다. 등록·수정·삭제 요청은 자동 재전송하지 않습니다. 새 포털 비밀번호를 저장할 때의 로그인 검증은 항상 새 세션으로 수행합니다.

앱 로그아웃, 앱 비밀번호 변경, 포털 연결 변경·삭제, 사용자 비활성화 시 해당 사용자의 캐시를 폐기합니다. 세션은 30분 미사용 또는 생성 후 8시간에 만료되며 최대 50개까지 보관합니다. 서버 재시작 시에는 새로 로그인합니다. 쿠키/토큰은 브라우저나 API 응답·로그·DB에 저장하지 않습니다.

입력창에서 Enter는 저장·적용 버튼으로 제출합니다. 취소·닫기는 별도 버튼이며 입력 검증 없이 닫을 수 있습니다. 실제 포털 전송 확인 모달의 취소 기본 포커스와 명시적 동의는 유지합니다.

## 기존 CLI

`시간표.js`는 사용자별 설정 파일(`users\사용자명.json`)을 읽어 월간 근무 일정을 생성하고, 중복 입력을 피하면서 신규 일지를 등록합니다.

## 1. 주요 기능

- 사용자별 설정 파일 기반 자동 입력
- 정기 근무 규칙(`regularRules`) + 특정일 예외(`specialDates`) + 휴가 제외(`vacationDates`)
- 공휴일 자동 제외: Google 한국 공휴일 ICS + 동양미래대 학사일정(개교기념일/보강일)
- 사용자 추가 공휴일(`extraHolidayDates`) 지원
- 기존 일지와 비교해 중복 일정 건너뛰기
- 옵션(`cleanupUnexpectedRows`)으로 예상 외 기존 행 삭제 시도
- 미승인 월/로그인 실패 등 주요 예외 메시지 처리
- 생성/신규 입력 대상의 전체 시수(총 분) 표시

## 2. 실행 환경

- Windows / macOS 13 이상(Intel 또는 Apple Silicon)
- Node.js 24 LTS 권장
- npm
- 크롬(또는 Chromium 실행 가능 환경)
- 인터넷 연결(공휴일/학사일정 조회)

## 3. 설치

```powershell
npm install
```

Puppeteer가 현재 Mac 아키텍처에 맞는 Chrome for Testing을 설치합니다. 시스템에 별도로 Chrome을 설치할 필요는 없습니다.

macOS에서는 설치 후 브라우저 실행 상태를 확인할 수 있습니다.

```bash
npm run check:macos
```

## 4. 기존 CLI 사용자 설정 파일 만들기

예시 파일을 복사해 본인 파일을 생성하세요.

Windows:

```powershell
Copy-Item .\users\사용자명.json.example .\users\내이름.json
```

macOS:

```bash
cp ./users/사용자명.json.example ./users/내이름.json
```

`users\내이름.json`에서 아래 항목을 수정합니다.

- `id`, `password`: 포털 로그인 계정
- `schedule.year`, `schedule.month`, `schedule.content`
- `regularRules`: 요일별 기본 근무 시간
- `specialDates`: 특정 날짜 시간 덮어쓰기
- `vacationDates`: 입력 제외 날짜
- `extraHolidayDates`: 공휴일로 추가 제외할 날짜(예: `[1, 19]`)
- `cleanupUnexpectedRows`: `true`면 이번 달 대상 날짜의 예상 외 행 삭제 시도

### 설정 예시

```json
{
  "id": "사용자ID",
  "password": "비밀번호",
  "schedule": {
    "year": 2026,
    "month": 1,
    "content": "실습실 점검"
  },
  "regularRules": [
    { "day": 1, "week": "월", "start": "0900", "end": "1700" },
    { "day": 2, "week": "화", "start": "0900", "end": "1700" }
  ],
  "specialDates": {
    "22": { "start": "1300", "end": "1800" }
  },
  "vacationDates": [15, 16],
  "extraHolidayDates": [1],
  "cleanupUnexpectedRows": false
}
```

## 5. 기존 CLI 실행

```powershell
npm run start:cli
```

실행 후 콘솔에 사용자 이름(파일명 기준, 확장자 제외)을 입력하세요.

예: `users\사용자.json` 파일을 쓸 경우 입력값은 `사용자`

## 6. 동작 순서

1. 사용자 설정 로드
2. 월간 일정 생성(공휴일/휴가/예외 반영)
3. 포털 로그인 및 근로장학생일지 화면 이동
4. 학년도/근로월 보정 후 조회
5. 기존 행 읽기 → 중복 제외/선택 삭제
6. 신규 일정만 입력 후 저장

## 7. 주의사항

- 포털 화면 구조(DOM)가 바뀌면 셀렉터 수정이 필요할 수 있습니다.
- 브라우저는 `headless: false`로 열리며, 완료 후 창이 자동으로 닫히지 않습니다.
- 사용자 계정 파일(`users\*.json`)은 민감 정보이므로 Git에 포함하지 마세요.

## 8. 트러블슈팅

### 로그인 후 진행이 멈춤/실패

- 계정 ID/비밀번호 확인
- 포털 점검 시간 여부 확인
- 포털의 UI 변경 시 `시간표.js`의 `SELECTORS` 점검

### 공휴일/학사일정 조회 실패

- 인터넷 연결 상태 확인
- 학교/Google 페이지 일시 장애 시 잠시 후 재실행

### macOS에서 브라우저가 열리지 않음

- `npm run check:macos`로 설치된 브라우저와 실행 권한 확인
- 실패하면 `node_modules`를 삭제한 뒤 `npm install` 재실행
- 회사 또는 학교 네트워크에서 Chrome 다운로드 주소가 차단되었는지 확인
