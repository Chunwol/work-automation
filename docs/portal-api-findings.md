# 동양미래대학교 포털 조회 API 조사

조사일: 2026-09-03, HTTP 전환·실제 등록/삭제 검증: 2026-09-04  
대상: 사용자 승인 테스트 계정의 근로장학생일지 조회 흐름  
범위: 로그인·조회 API 확인 후 사용자 승인에 따라 테스트 일지 1건 등록·재조회·삭제. 기존 기록 변경 없음.

## 결론

근로장학생일지 조회는 브라우저 DOM을 읽지 않고 포털 내부 JSON API로 직접 조회할 수 있습니다. 단, 공개 API는 아니며 포털 SSO 로그인으로 생성된 유효한 세션 쿠키가 반드시 필요합니다.

- 엔드포인트: `POST https://dmis.dongyang.ac.kr/sub.SubWorkSchoE.do`
- 요청 형식: `application/json`
- 인증: HTTP 로그인과 SSO 이동 후 발급된 세션 쿠키(요청 작업별 CookieJar)
- 승인 배정과 월간 기록을 각각 조회하고 화면 결과와 일치함을 확인
- 포털 코드 카탈로그: 장학 유형 10개, 근무부서 44개
- 세션 없는 동일 요청: HTTP 200과 JSON은 반환하지만 데이터 대신 `로그인 세션이 종료되었습니다` 오류 반환

웹 애플리케이션은 HTTP로 로그인 폼을 읽고 `/proc/Login.do`에 아이디·비밀번호를 전송한 후 SSO 이동을 따라갑니다. 이후 업무 JSON API에는 비밀번호 대신 쿠키와 메뉴 권한 컨텍스트를 사용합니다. Chromium이나 화면 클릭은 필요하지 않습니다. 공개 OAuth/Open API가 아니라 학교의 기존 세션 기반 내부 API입니다.

## 요청 순서

| 순서 | `strCommand` | 역할 | 주요 응답 |
|---:|---|---|---|
| 1 | `OnLoad` | 화면 초기 데이터 | 장학금 코드, 근로부서 목록, 시스템 날짜 |
| 2 | `FindWork` | 대상 연월의 근로 배정 조회 | `listStdno` |
| 3 | `Bef` | 이전·누적 근로시간과 한도 확인 | `tot_work_time`, `limit_yn` |
| 4 | `List` | 실제 근로일지 목록 조회 | `listMain`, `listStdt` |
| 5 | `Chgdeptcd` | 장학금 선택에 따른 부서/장학 목록 갱신 | `listSchoCd`, `listWorkDeptCd` |
| 6 | `Checkweek` | 날짜의 요일과 포털 주차 | `CheckDate`, `week_cnt` |
| 7 | `Vacation` | 해당 날짜 방학 구분 | `strRemark` |
| 8 | `Holi` | 포털 공휴일 | `listHoliday` |
| 9 | `Save` | 신규 행 등록, 요청 후 재조회 검증 | 실제 `List` 반영 여부 확인 |

업무 명령 외에도 화면 진입 과정에서 다음 별도 API가 호출됩니다.

| 엔드포인트 | 명령 | 역할 |
|---|---|---|
| `/sys.Main.do` | `MenuAuth` | 근로장학생일지 메뉴 권한 확인 |
| `/cmn.CmnAppHeader.do` | `Onload` | 공통 헤더와 사용자 권한 컨텍스트 로드 |

즉, `/sub.SubWorkSchoE.do`라는 URL 하나에 여러 `strCommand`가 라우팅되는 구조일 뿐, `List` 한 번만 호출하는 구현이 아닙니다.

## 장학 유형과 근무지 처리

`OnLoad`의 전체 카탈로그에는 국가근로(교내·교외), 일반근로, 국고사업, 원격사업, 장애학생도우미, 특별근로 등의 유형이 포함됩니다. 그러나 자동입력 선택지에는 이 전체 목록을 그대로 노출하지 않습니다. `FindWork`가 해당 계정·연월에 반환한 승인 조합만 후보로 사용합니다.

- 각 승인 조합마다 `Bef`와 `List`를 별도로 호출
- 조회 결과에 장학 코드·근무부서 코드를 포함하고, 중복 검사는 선택한 배정 범위 안에서 수행
- 하나의 배정만 있으면 자동 선택, 여러 배정이면 사용자 명시 선택
- 자동입력 직전에 같은 계정·연월로 `FindWork`를 다시 호출해 선택값 재검증
- 선택한 조합의 `List`만 중복 검사와 저장 후 검증에 사용
- 승인 배정이 사라지면 입력 중단. `limit_yn=Y`는 학기당 640시간 한도의 예외이며 입력 금지가 아님
- 다른 승인 배정의 기록도 시간 겹침·하루 8시간 검증에 포함

이 구조이므로 다른 사용자가 일반근로와 국가근로를 동시에 승인받거나 근무지가 여러 곳이어도 기록을 한데 섞지 않습니다.

`List` 요청의 `data.requestKey`에서 확인한 주요 필드는 다음과 같습니다.

```json
{
  "strYear": "2026",
  "strMonth": "06",
  "strSchoCd": "<장학금 코드>",
  "strWorkDeptCd": "<근로부서 코드>",
  "strStudentNo": "<세션 사용자 학번>",
  "strStudentNm": "<세션 사용자 이름>"
}
```

개인 식별값과 세션 정보는 진단 결과에 기록하지 않습니다.

## 웹 구현 방침

- 조회·중복 확인·입력 후 검증: 확인된 `List` API 사용
- 배정 후보: `FindWork` 결과만 사용하고, 배정별로 `Bef`와 `List` 호출
- 신규 입력과 저장: 공식 화면에서 확인한 `Save` JSON 형식, `sts=i` 신규 행만 전송
- 수정/삭제: 사용자가 명시 확인한 본인 미확인 행만 `sts=u`/`sts=d`로 처리. 신규 자동입력 중에는 수정/삭제를 자동으로 수행하지 않음
- API 응답에 일지 목록이 없거나 세션 오류가 있으면 작업 실패 처리
- 계정, 쿠키, 학번, 이름은 작업 로그에 기록하지 않음

공식 화면 스크립트 `https://dmis.dongyang.ac.kr/ui/app/sub/SubWorkSchoE.clx.js`의 입력 규칙을 서버에 적용했습니다. 최소 1시간, 30분 단위 근로시간, 국가근로 시작 10분 단위·일반근로 시작 30분 단위, 하루 8시간, 승인기간, 공휴일과 한도를 검사합니다. `NAT_AMT`가 0이 아닌 경우 주간/야간·방학에 따른 주·월 한도도 적용합니다. 응답에서 값이 없으면 공식 화면과 동일하게 빈 값을 사용합니다.

`Save` 메타데이터는 `_PATAM_AS_TABLE=["subworkmaster,sub_work_master,dsListMain"]`이며 기본키는 `YEAR,SEQ,SCHO_CD,WORK_DEPT_CD,WORK_DT,STUDENT_NO`입니다. `__origin` 키를 포함하고 사용자 승인 상태는 임의로 변경하지 않습니다. 저장 응답이 불확실해도 재전송하지 않고 `List`로 날짜·시간·내용을 확인합니다. 1~2월 조회의 `strYear`는 전년도 학년도이고 신규 행 `YEAR`는 실제 달력 연도입니다.

- 회원가입 API → 암호화 계정 저장 API → 9월 일정 저장 API → 작업 API → HTTP SSO → 학교 `Save` → `List` 검증을 통과
- 테스트 행: 2026-09-01 13:00~14:00, `API test DELETE`와 고유 표식을 근무내용으로 사용
- 신규 1건 확인 후 같은 표식·기본키·시간의 본인 미승인 행만 삭제
- 학교 기록 수 `0 → 1 → 0`, 원래 기록과 최종 기록 비교 일치
- 웹 테스트 계정과 포털 암호문은 메모리 DB에만 저장해 종료 시 제거
- 비밀값 없는 실행 결과: `artifacts/portal-http-roundtrip.json`

학교 내부 API는 변경될 수 있으며 모든 장학 유형의 실계정 쓰기를 검증한 것은 아닙니다. 실제 쓰기는 승인된 국가근로(교내) 배정에서 확인했고, 다중 배정·일반근로 분기 등은 모의 응답 테스트로 검증했습니다. 직원용 타 학생 검색·승인 API는 사용하지 않습니다.

## 8월 추가 확인 및 달력 관리

읽기 전용 조회로 한 달 안에 국가근로와 일반근로가 모두 존재하는 경우를 확인했습니다. 개인 근무내역은 공개 문서에 포함하지 않습니다. 승인기간은 실제 근무 전환일보다 넓을 수 있으므로 승인기간만으로 날짜별 배정을 자동 확정하면 안 됩니다. 기존 일지는 변경하지 않았습니다.

수정 `sts=u` 형식은 먼저 공식 화면에서 전송을 차단한 상태로 직렬화 결과를 확인했고, 모의 포털 응답과 UI 테스트를 거쳤습니다. 이후 사용자가 9월 테스트를 명시 승인하여 아래 실제 수정 검증도 수행했습니다. 8월 일지는 계속 읽기 전용이며 수정하거나 삭제하지 않았습니다.
