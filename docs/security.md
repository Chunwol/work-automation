# 보안 운영 안내

## 로컬 사용

기본값은 `127.0.0.1:3210`으로 이 컴퓨터에서만 접속할 수 있습니다. 앱 로그인 비밀번호는 해시되고, 학교 포털 계정은 AES-256-GCM으로 암호화되어 SQLite에 저장됩니다.

로컬 키 `data\.master-key`가 데이터베이스와 같은 PC에 있으므로 Windows 사용자 계정 자체가 침해되면 완전한 보호를 보장할 수 없습니다. Windows 로그인 암호와 디스크 암호화(BitLocker)를 함께 사용하는 것을 권장합니다.

## 외부 공개 전 필수 항목

1. Node.js LTS 버전 사용
2. HTTPS 리버스 프록시 적용
3. `NODE_ENV=production`
4. `COOKIE_SECURE=true`
5. 32바이트 `APP_MASTER_KEY`를 서버의 비밀 저장소에서 주입
6. 첫 관리자 생성 보호를 위한 임의의 `SETUP_TOKEN` 설정
7. 프록시를 사용할 때만 `TRUST_PROXY=true`
8. 방화벽에서 필요한 사용자·네트워크만 허용
9. `data` 폴더의 운영체제 파일 권한 제한
10. 정기적인 `npm audit` 및 백업 복구 시험

키 생성 예시:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

`APP_MASTER_KEY`를 잃으면 저장된 포털 계정을 복호화할 수 없습니다. 키를 변경하려면 기존 값을 먼저 복호화해 새 키로 재암호화하는 별도 마이그레이션이 필요합니다.

## 데이터 처리 원칙

- API 응답에 포털 비밀번호를 반환하지 않음
- 포털 아이디는 마스킹된 형태만 반환
- 세션 토큰 원문은 DB에 저장하지 않음
- CSRF 토큰이 없는 변경 요청은 거절
- 사용자별 일정·포털 계정·작업 이력 분리
- 일반 사용자의 관리자 API 접근 거절
- 자동화 로그에 계정, 쿠키, 토큰, 학번, 이름을 기록하지 않음
- 중복된 일정은 건너뛰고, 자동 삭제는 수행하지 않음
- 자동입력 전 선택한 장학 유형·근무지를 해당 월의 포털 승인 배정과 재검증
- 승인 배정 미선택·불일치, 권한/응답 형식 불명, 겹치는 시간과 근로 한도 초과 시 입력 중단
- `limit_yn=Y`는 학기 한도 예외이며 입력 금지가 아님. `N`일 때 적용 장학 유형의 640시간 한도 검사
- 회원가입은 일반 사용자 권한만 부여하고 관리자 초기 설정과 분리
- 가입 횟수 제한, 비밀번호 확인, 교차 출처 인증 요청 차단
- HTTP SSO 이동은 지정된 학교 HTTPS 서버만 허용하고 다른 출처로 비밀번호 본문 재전송 금지
- 동일 학교 계정의 동시 쓰기를 차단하며, 대기 중인 작업은 요청 시점의 일정으로 실행
- 저장 응답 유실 시 재조회만 수행하며 무조건 재전송하지 않음
- 미래 일지는 앱 일정으로만 보관하고, 실제 근무 종료 전에는 포털 쓰기 차단
- 일반 자동입력은 신규 행만 저장. 테스트 정리는 승인된 표식·기본키·시간의 본인 미승인 행 1건만 삭제
- 사용자 명시 요청에 따른 포털 수정·삭제는 CSRF와 확인 동의가 필요하며, 본인 계정의 미확인 원본을 재조회해 기본키·시간·내용이 일치하는 행 1건만 처리
- 확인 완료 행과 확인 날짜가 있는 행은 수정·삭제 차단. 원본 변경 감지 시 새 조회 요구
- 공휴일 근무 예외는 앱 일정 제외만 해제하며 학교의 장학 유형별 공휴일 등록 금지나 시간 제한을 우회하지 않음
- 조회 결과 캐시는 사용자·월·학교 계정 등록 시각으로 제한하고 학교 계정 변경 시 이전 결과 표시 차단

현재 동시 실행 잠금과 가입/로그인 제한은 단일 Node 프로세스 기준입니다. 다중 서버 배포에는 공유 잠금·공유 요청 제한 저장소와 별도 운영 검토가 필요합니다. 외부 공개나 배포는 이번 변경에 포함하지 않았습니다.
